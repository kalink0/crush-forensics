### Media Viewer

Plays audio and video files (MP4, MOV, MP3, M4A, AAC, WAV, etc.) using the system multimedia backend.

A file is opened here by its extension or, renamed or without one, by its content: an ISO base media file (MP4, MOV, M4A, 3GP …, by its `ftyp` box; an image brand such as HEIC or AVIF goes to the Image Viewer), RIFF WAVE and AVI, FLAC, Matroska/WebM (EBML header), ASF (WMA/WMV), Ogg, AMR, and MP3 with an ID3v2 tag. MP3 without an ID3v2 tag, AAC in ADTS and QuickTime files that don't open with an `ftyp` box start with no signature of their own and are recognised by their extension only.

**C2PA (Content Credentials) detection** works as in the [Image Viewer](image-viewer.md), with the same Properties rows, for every audio/video container the C2PA spec (2.4, Annex A) defines an embedding for, recognised by content: BMFF files with an `ftyp` box of any brand (MP4, MOV, M4A, M4V, 3GP …; top-level `uuid` box with box_purpose `manifest`, `original` or `update`), RIFF WAVE and AVI (`C2PA` chunk), an ID3v2.2/2.3/2.4 tag at the start of the file — MP3, and FLAC with a prepended ID3v2 tag — (GEOB frame with the media type `application/c2pa` or the older `application/x-c2pa-manifest-store`), and Ogg (a logical bitstream whose first packet starts with `\x00c2pa`). An original and an update Manifest Store (an update manifest chain in BMFF) are both shown, numbered. BMFF `merkle` boxes hold Merkle tree hash data, not a Manifest Store; they are counted with their offsets under `C2PA scan notes`. Compressed or encrypted ID3 GEOB frames are listed there as not checked. FLAC starting with its own `fLaC` marker, Matroska/WebM, ASF and AMR have no embedding defined by the spec and say so; MP3 without an ID3v2 tag and AAC in ADTS, recognised by their extension only, are reported as not checked.

**XMP Digital Source Type** is read from audio and video files the same way as from images (container-agnostic packet search).
